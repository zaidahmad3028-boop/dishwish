# API

Interactive docs: `http://localhost:8000/docs` (Swagger UI, generated by FastAPI) while the API runs.

Signed-in routes need `Authorization: Bearer <Supabase access token>`. Request bodies reject unknown fields (`extra="forbid"`), so a client can't slip in a `user_id`. Errors return `{"detail": "..."}` with 401 (no or bad session), 404, or 422 (validation); internal errors never include stack traces.

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| GET | `/api/health` | public | Liveness |
| GET | `/api/me` | user | Echo the verified user id and email |
| POST | `/api/recommendations` | user | Curated recipe ranking (see RECOMMENDATION_ENGINE.md) |
| GET | `/api/curated/{slug}?have=...` | public | Curated recipe with ingredients (have/missing), steps, nutrition estimate, diets, allergens |
| GET | `/api/compatibility/{name}` | public | Stored graph edges of one ingredient |
| POST | `/api/compatibility/check` | public | Pairwise compatibility of a selection plus graph-suggested additions |
| POST | `/api/recommend` | public | Legacy ingredient pairing suggestions (generator page) |
| POST | `/api/recipes` | user | Template recipe generator |

### `POST /api/recommendations`

```json
{
  "ingredients": ["Chicken Breast", "Tomato"],
  "tastes": {"spicy": "high"},
  "allergens": ["milk"],
  "blocked_words": ["prawns"],
  "diets": ["gluten_free"],
  "pantry": ["Garlic"],
  "max_minutes": 45,
  "limit": 12
}
```

Response: `recipes[]` (slug, name, match_percent, score, components, weights_used, penalty, used, missing, explanation, nutrition_per_serving, diets…), `suggestions[]`, `excluded` counts (allergy, diet, no_overlap), the `settings` used, `data_source` (`database` or `bundled`) and `notes`.

## Data API (Supabase)

User and admin data go through Supabase's REST/RPC API with the user's JWT; row-level security decides access. See [DATABASE.md](DATABASE.md) for the tables and RPCs. Rate limiting for sign-in, sign-up and email sends is Supabase's (Authentication → Rate Limits).
